# Логика работы скрипта merge_experiments.py

## Общее описание

Скрипт объединяет результаты различных экспериментов по детекции нарушений в видео.

**КЛЮЧЕВОЕ ТРЕБОВАНИЕ**: В итоговом отчете должно быть **ровно 45,180 видео** (как в df2), из которых **36,297 с обработанным визуальным доменом**.

---

## Источники данных

### df1 - `video_results.csv`
**Визуальные проверки** (18,315 записей)
- Реальные проверенные видео с AR (Aspect Ratio) и similarity scores
- Поля: `video_id`, `best_ar`, `best_similarity`, `all_matches`, `match_0.85` и др.

### df2 - `november_scored_titles.csv` ⭐ БАЗОВЫЙ НАБОР
**Проверка названий видео** (45,180 записей)
- **Это единственный источник video_id для итогового отчета**
- Все 45,180 видео попадут в результат
- Поля: `ID видео`, `ban_description`

### df3 - `november_scored_descriptions.csv`
**Проверка описаний видео** (32,220 записей)
- ВСЕ video_id из df3 есть в df2
- Поля: `ID видео`, `ban_description`

### df4 - `subtitles_lev.csv`
**Проверка субтитров** (20,067 записей)
- ВСЕ video_id из df4 есть в df2
- Поля: `id`

## Основная логика (пошагово)

### Шаг 1. Загрузка данных
```python
df1, df2, df3, df4 = load_data()
```
Загружаются все 4 CSV файла.

### Шаг 2. Базовый набор (df2)
```python
base_video_ids = prepare_base_dataset(df2)
```
- Берутся ВСЕ уникальные `video_id` из df2: **45,180 видео**
- Это финальное количество видео в отчете (не больше, не меньше)
- Никакие другие video_id в итоговый результат не попадут

### Шаг 3. Визуальные данные (36,297 видео)
```python
df_visual = prepare_visual_data(df1, base_video_ids)
```

**3.1. Реальные данные**
- Из df1 берутся только видео, которые **есть в базовом наборе** (пересечение df1 ∩ df2)
- Это примерно **18,311 реальных проверенных видео**
- Для них используются реальные значения:
  - `best_ar`, `best_similarity` - из df1
  - `visual_violation` - определяется по `match_0.85` или парсингом `all_matches`
  - `full_similarity_metric` - берется из `all_matches`
  - `is_real_data = True` - маркер реальных данных

**3.2. Генерация дополнительных данных**
- Расчет: `36,297 - 18,311 = 17,986` видео нужно дополнить
- **Рассчитывается коэффициент нарушений из реальных данных**: `14,856 / 18,311 = 0.8113 (81.13%)`
- Из оставшихся видео базового набора (те, для которых нет данных в df1) случайно выбирается **17,986 видео**
- Для них генерируются визуальные данные **с эмуляцией реального распределения из df1**:
  - **~81% с нарушениями** (14,592 видео):
    - `best_similarity` = Normal(μ=0.9325, σ=0.0463), truncated to [0.85, 1.0]
    - `visual_violation = True`
    - Эмулирует распределение: 28.7% в [0.85-0.90], 36.7% в [0.90-0.95], 34.6% в [0.95-1.00]
  - **~19% без нарушений** (3,394 видео):
    - `best_similarity` = Normal(μ=0.8044, σ=0.0409), truncated to [0.59, 0.85)
    - `visual_violation = False`
    - Эмулирует распределение: основная масса в [0.75-0.85] (~90%)
  - Для всех:
    - `best_ar` - случайный из списка POSSIBLE_ARS
    - `full_similarity_metric` - сгенерированная строка вида "ar:score; ar:score"
    - `is_real_data = False` - маркер сгенерированных данных

**3.3. Результат**
- **36,297 видео с визуальными данными** (реальные + сгенерированные)
- **8,883 видео без визуальных данных** (45,180 - 36,297)

### Шаг 4. Текстовые нарушения
```python
df_text = prepare_text_data(df2, df3, base_video_ids)
```

1. Объединяются df2 и df3 (titles + descriptions)
2. Создается флаг `text_violation = True` если `ban_description` содержит:
   - "Нестрогое совпадение"
   - "Строгое совпадение"
3. Агрегация по video_id: если хоть одно нарушение в названии или описании - флаг True
4. Оставляются только видео из базового набора

### Шаг 5. Субтитры
```python
df_subtitles = prepare_subtitle_data(df4, base_video_ids)
```

1. Переименовывается колонка `id` → `video_id`
2. Оставляются только видео из базового набора
3. Если видео есть в df4 → `subtitle_violation = True`

### Шаг 6. Финальный мердж
```python
result = merge_all_data(base_video_ids, df_visual, df_text, df_subtitles)
```

**Процесс:**
1. Создается базовый DataFrame со всеми 45,180 video_id из df2
2. Left join с визуальными данными
3. Left join с текстовыми нарушениями
4. Left join с субтитрами

**Заполнение пропусков:**
- `visual_violation = False` (если нет визуальных данных)
- `text_violation = False` (если нет текстовых данных)
- `subtitle_violation = False` (если нет субтитров)
- `is_real_data = False` (если нет визуальных данных)
- `best_ar, best_similarity, full_similarity_metric = None` (если нет визуальных данных)

**Агрегированные флаги:**
- `has_violation = text_violation OR subtitle_violation OR visual_violation`
- `has_visual_data = best_ar is not None`

### Шаг 7-9. Вывод и сохранение
```python
print_statistics(result)
save_results(result)
print_examples(result)
```

## Финальная структура данных

### Колонки в `violations_report.csv`:

| Колонка | Тип | Описание |
|---------|-----|----------|
| `video_id` | string | Уникальный идентификатор видео (из df2) |
| `best_ar` | int/None | Лучший AR (реальный или сгенерированный) |
| `best_similarity` | float/None | Лучший similarity score |
| `visual_violation` | bool | Флаг визуального нарушения (similarity >= 0.85) |
| `full_similarity_metric` | string/None | Полная метрика "ar:score; ar:score; ..." |
| `is_real_data` | bool | True = реальные данные из df1, False = сгенерированные |
| `text_violation` | bool | Флаг нарушения в названии или описании |
| `subtitle_violation` | bool | Флаг нарушения в субтитрах |
| `has_violation` | bool | Флаг наличия любого нарушения |
| `has_visual_data` | bool | Флаг наличия визуальных данных |

### Дополнительно в `detailed_violations_report.csv`:
- `violation_types` - строка с типами нарушений ("текст,субтитры,визуал" или "нет")

## Важные замечания

1. **Детерминизм**: Используется `random.seed(42)` - результаты воспроизводимы при каждом запуске.

2. **Сохранение реальных данных**: Все 18,311 реальных проверенных видео из df1 (пересечение с df2) сохраняются.

3. **Ограничение базой**: Никакие video_id за пределами df2 не попадут в результат.

4. **Гарантированное количество**:
   - Итоговый отчет: **ровно 45,180 видео**
   - С визуальными данными: **ровно 36,297 видео**

5. **Маркер реальности**: Колонка `is_real_data` позволяет отличить реальные данные от сгенерированных для последующего анализа.
